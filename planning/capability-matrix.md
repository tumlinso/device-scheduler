# Capability and evidence matrix

This matrix separates implemented code and local test coverage from live qualification. Package code exists for many contracts, but mock-backed tests do not establish behavior of the running daemon, systemd user manager, GPUs, or FrameShift service.

| Capability | Implemented in repository | Current evidence and limit |
|---|---|---|
| Core domain and policies | Resource/job/lease/handoff models, request validation, allocator, weighted policy, schedule logic, application operations, explanations and replay. | Unit tests cover local contracts and policy behavior. No production package has been released or deployed. |
| Durable ledger | SQLite ledger with entities, transactions, operation/event recording, idempotency, artifacts and backup support. | Temporary-database tests cover persistence behavior. Live CPU daemon crash recovery passed in receipts 04 and 05. Production backup/restore and upgrade migration qualification remain pending. |
| Lease admission and reclamation | Atomic logical allocations, fencing and explicit reclamation states; expired/unknown capacity is not treated as free. | Allocator tests use a local ledger. External GPU/process cleanup and cross-process contention remain unqualified. |
| NVIDIA inventory and topology | `nvidia-smi` discovery, compute-process observations, topology/conflict domains, and explicit advisory memory accounting. | Adapter tests use a fake command runner. The host snapshot in [contracts](contracts.md) is observational only; no live V100 adapter/quiescence/reclamation qualification has been recorded. |
| Linux process execution | A systemd user-unit adapter with deterministic attempt unit names, invocation identity, cgroup checks, resource properties, logs and cancellation. | The live CPU systemd receipt `device-scheduler-systemd-qualification-2gmis0qs/receipt.json` passes 11 checks, including configured limits, process-tree cleanup and fresh-process reconciliation. GPU process execution remains pending. |
| Daemon composition and local recovery | One application service composes the ledger, scheduler, adapters and reconciliation routes. | Live daemon receipt 05 verifies one CPU attempt and its exact systemd invocation survive SIGKILL/restart with one physical launch and verified cleanup. Host-reboot recovery remains pending. |
| Managed model backend | Backend profiles, readiness/drain/evict/restore interfaces and residency leases are implemented. | Adapter/coordinator tests use fake backends. No live llama.cpp start, readiness, unload or memory reclamation evidence. |
| FrameShift continuation adapter | Loopback endpoint adapter for consumer registration, durable suspend barriers, result delivery and resume. | Real FrameShift Engine/SQLite restart tests and affected FrameShift service tests pass. Live GPU/model-backed pending-tool resumption remains pending. |
| Explicit handoff | Finite batch coordinator, explicit eviction grants, round-trip reservation, safe drain, durable phase journal, result retention, restore and resume logic. | Coordinator tests use fake backend, job and continuation adapters. The full GPU/model/FrameShift journey and phase-by-phase live restart recovery remain pending. |
| Jobs, schedules and events | Job operations, delayed/recurring schedules, dependencies, event deduplication and policy admission. | Unit tests cover local state and fake events. Live timer/service restart, workload execution and operational behavior remain pending. |
| MCP, SDK and CLI | Loopback HTTP MCP service, authenticated client, stdio proxy and common CLI operation surface. | Live daemon receipt 05 verifies authenticated SDK submission, CLI access to the same job, readiness polling, and denied unauthenticated MCP. Persistent deployment, stdio handshake and full permission qualification remain pending. |
| Security and command profiles | Scoped principals, host-managed token/config paths, approved execution profiles, secret-reference validation and bounded command arguments. | Local validation/authentication tests only. No deployment threat review or live permission audit. Same-user cgroups are not hostile-tenant isolation. |
| Observability and replay | Decision explanations, health/reconciliation views, evidence snapshots, bounded output and policy simulation. | Unit tests cover structured output and no-side-effect replay contracts. No operational evidence-retention or user review qualification. |
| Project Control resource integration | A compatibility adapter and opt-in consumer migration are being implemented. | Source preparation is distinct from live activation. Project Control task, workspace, agent, Todo and acceptance authority remains separate. Consumer qualification and cutover remain pending. |
| CUDA controller retirement | Retirement is a planned DS-13 gate, not an implemented behavior. | Existing controller/allocation paths remain active. No migration, old-admission fence, single-authority audit or disablement evidence. |
| Multi-host and hostile-tenant isolation | Deferred from first release. | No implementation or capability claim. |

## Required live qualification

Record systemd transient-unit authorization and resource controls, live MCP startup/health/authentication, GPU inventory and verified reclamation on an isolated pool, live FrameShift suspension and result delivery, failure/restart behavior across every handoff phase, and single-authority CUDA-controller cutover separately. The checklist and evidence slots are in [qualification-v1](qualification-v1/README.md). Until those records are populated, these capabilities remain pending regardless of local test results.
