# Capability and evidence matrix

This matrix separates repository implementation, automated test evidence, and live qualification. Its status reflects the 2026-10-23 generic service qualification and receipts linked below; it does not promote untested behavior to a capability guarantee.

| Capability | Implemented in repository | Current evidence and limit |
|---|---|---|
| Core domain and policies | Resource/job/lease/handoff models, validation, allocator, weighted policy, schedules, application operations, explanations and replay. | The host suite [report](qualification-generic-v1/tests.xml) records 342 tests, zero failures, errors, or skips. This is software test evidence, not a production release or broad adapter guarantee. |
| Durable ledger and daemon recovery | SQLite ledger, idempotency, operation/event history, artifacts and backups; daemon reconciliation on startup. | Live CPU [receipt 07](qualification-v1/daemon-receipt-07.json) passes 14 checks. The same attempt and systemd invocation survived daemon `SIGKILL`/restart with one physical launch and verified cleanup. Host-reboot and production backup/upgrade recovery remain pending. |
| Lease admission and reclamation | Atomic logical allocations, fencing and explicit reclamation states; CPU/memory supervised leases bind one scheduler job at a time and remain reserved for renewal/reuse after job completion. Uncertain capacity remains unavailable. | Real GPU [allocation receipt](qualification-v1/gpu-allocations-passed.json) verifies shared coexistence, exclusive waits for shared cleanup, reclamation before exclusive execution, unmanaged-process blocking and resume after cleanup. The [generic workflow](qualification-generic-v1/workflow.json) also verifies CPU/memory lease execution, renewal and release. Unmanaged in-process CPU/memory consumption is unsupported; cross-host contention is out of scope. |
| NVIDIA inventory and topology | `nvidia-smi` discovery and compute-process observations; advisory memory budgets and topology-derived conflict domains. | The GPU receipt records live V100 admission scenarios. Memory budgets are accounting rather than hardware-enforced limits. The profiler/topology scenario was skipped because no isolation domain includes the granted GPU; broader topology qualification remains pending. |
| Linux process execution | A systemd user-unit adapter with deterministic attempt identity, cgroup checks, resource properties, logs and cancellation. | [Systemd receipt](qualification-v1/device-scheduler-systemd-qualification-2gmis0qs/receipt.json) passes 11 live CPU adapter checks; daemon receipt 07 separately covers same-invocation recovery across daemon restart. GPU execution is covered by the earlier real handoff and allocation receipts. The latest [production restart](qualification-generic-v1/restart.json) preserved one attempt/invocation and one physical launch. Host-reboot recovery remains unqualified. |
| Managed model backend | Backend profiles, readiness/drain/evict/restore interfaces and residency leases. | Backend ownership and reservation behavior has automated coverage. The [real handoff](qualification-v1/gpu-handoff-passed.json) verifies model unload, physical reclamation and pinned restoration/readiness. |
| FrameShift continuation adapter | Loopback endpoint adapter for consumer registration, durable suspend barriers, result delivery and resume. | The host suite passes, and earlier focused Engine/SQLite restart tests are recorded in [qualification history](qualification-v1/README.md). The actual model completed generation 2 after durable result delivery/resumption; the full failure-phase matrix remains pending. |
| Explicit handoff | Finite batch coordinator, explicit eviction grants, round-trip reservation, safe drain, durable phases, result retention, restore and resume. | Automated tests pass. The real handoff passed all 17 checks; ordinary suspension preserved model residency, and weight unloading requires an explicit authorized finite request. |
| Jobs, schedules and events | Job operations, delayed/recurring schedules, dependencies, event deduplication and policy admission. | The live generic workflow verifies real CPU/memory jobs, delayed and interval schedules, dependencies, event gates/deduplication, cancellation and cleanup. Calendar/DST behavior is covered by tests; its full live boundary matrix remains unqualified. |
| MCP, SDK and CLI | Loopback HTTP MCP service, authenticated client, stdio proxy and common CLI operation surface. | Live daemon receipt 07 verifies readiness/health, authenticated SDK submission, CLI access to the same job, and denied unauthenticated MCP. The generic workflow verifies authenticated SDK/MCP, CLI and stdio reads against one canonical job. CLI discovers the installed user config. Full permission/threat qualification remains unqualified. |
| Security and command profiles | Scoped principals, host-managed token/config paths, approved execution profiles, secret-reference validation and bounded command arguments. | Local validation/authentication tests only. Unauthenticated MCP is denied; generic own-work lease/schedule/event grants are enabled without broadening execution roots or backend rights. No hostile-tenant threat qualification. Same-user cgroups are not hostile-tenant isolation. |
| Observability and replay | Decision explanations, health/reconciliation views, evidence snapshots, bounded output and policy simulation. | The generic workflow verifies logs, policy explanations and side-effect-free priority/fairness simulation. Extended artifact-retention and operational policy replay qualification remain unqualified. |
| Project Control resource integration | A compatibility adapter is implemented for resource ownership and allocation calls. | The production resource facade lease/heartbeat/release test passed; consumers are switched and legacy admissions fenced. Project Control retains project, workspace, agent, Todo and acceptance authority. DS-00 is natively accepted, but its Git integration is finalized dirty with no resulting source; see [native status](qualification-v1/native-status.md). |

| Multi-host and hostile-tenant isolation | Deferred from first release. | No implementation or capability claim. |

## Required live qualification

Remaining qualification includes the full handoff failure/restart matrix and the skipped topology/profiler isolation case on a qualified domain. See [qualification-v1](qualification-v1/README.md). The old controller is retired for the migrated pool; keep one allocator active during operation or rollback.
